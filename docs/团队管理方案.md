# Sub2API 团队管理功能 — 完整实施方案（Phase 1-3，Phase 4 延后）

---

## 一、核心概念定义

### 1.1 概念模型

| 概念 | 说明 | 关系 |
|------|------|------|
| **User** | 平台登录账号，一个自然人 | 可属于多个 Team |
| **Team** | 团队/组织，成本核算和权限管理的顶级容器 | `teams.id = users.id`（一对一映射） |
| **Department** | 团队内部的部门/组，用于成本归集和权限隔离 | Team 1:N Department |
| **Consumer** | 消费主体，可以是人、应用或服务账号 | Department 1:N Consumer |
| **API Key** | 实际调用接口的凭证 | Consumer 1:N API Key |

### 1.2 核心设计原则

1. **最小改动原则**：`teams.id = users.id`，现有所有 `user_id` 字段保持不变，无需大规模迁移
2. **向下兼容原则**：没有团队的存量用户自动获得一个独立团队
3. **渐进增强原则**：Phase 1 做基础 CRUD + 统计，Phase 2 做性能优化，Phase 3 做增强功能
4. **Phase 4 延后原则**：企业集成（LDAP/OIDC/SSO/成本分摊Webhook）暂不实施，待有明确客户需求后再启动

### 1.3 `teams.id = users.id` 语义说明

> `teams.id` 与 `users.id` 一一对应，但**不表示只有 owner 一个用户**。`team_members` 表支持将其他 `users` 加入团队（role = admin/member/viewer），实现多管理员和分级权限。`teams.id = users.id` 仅保证存量数据的平滑迁移，不限制多人协作。

**示例：**
- 用户 A（id=100）创建团队 → `teams.id=100, owner_id=100`
- 用户 B（id=200）被 A 邀请加入团队 → `team_members.team_id=100, user_id=200, role=member`
- 所有现有表的 `user_id=100` 和 `user_id=200` 保持不变，各自归属自己的团队

## 三、数据迁移脚本

### 3.1 为已有用户创建团队

```sql
-- 1. 为每个已有 user 创建 team（id 与 user.id 保持一致）
INSERT INTO teams (id, name, slug, owner_id, settings, created_at, updated_at)
SELECT 
    u.id AS id,
    COALESCE(u.username, u.email) AS name,
    LOWER(REPLACE(COALESCE(u.username, u.email), ' ', '-')) AS slug,
    u.id AS owner_id,
    '{}'::jsonb AS settings,
    u.created_at,
    u.updated_at
FROM users u
WHERE u.deleted_at IS NULL
  AND NOT EXISTS (SELECT 1 FROM teams t WHERE t.id = u.id);

-- 2. 标记用户已初始化
UPDATE users SET team_initialized = TRUE WHERE deleted_at IS NULL;

-- 3. 创建 team_members（owner）
INSERT INTO team_members (team_id, user_id, role, joined_at, created_at, updated_at)
SELECT 
    t.id AS team_id,
    u.id AS user_id,
    'owner' AS role,
    u.created_at AS joined_at,
    NOW(),
    NOW()
FROM users u
JOIN teams t ON t.owner_id = u.id
WHERE u.deleted_at IS NULL
  AND NOT EXISTS (SELECT 1 FROM team_members tm WHERE tm.team_id = t.id AND tm.user_id = u.id);

-- 4. 同步 teams 表自增序列，防止后续插入冲突
SELECT setval('teams_id_seq', (SELECT COALESCE(MAX(id), 1) FROM teams));
```

### 3.2 为已有 API Key 创建默认 Consumer

```sql
-- 1. 为每个 team 创建一个默认 consumer
INSERT INTO consumers (team_id, department_id, type, name, email, status, created_at, updated_at)
SELECT 
    t.id,
    NULL,
    'service_account',
    'Default Consumer',
    u.email,
    'active',
    NOW(),
    NOW()
FROM teams t
JOIN users u ON u.id = t.owner_id
WHERE NOT EXISTS (
    SELECT 1 FROM consumers c WHERE c.team_id = t.id AND c.name = 'Default Consumer'
);

-- 2. 将已有 api_keys 关联到默认 consumer，同时填充 team_id
UPDATE api_keys ak
SET 
    team_id = ak.user_id,  -- teams.id = users.id
    consumer_id = (
        SELECT c.id 
        FROM consumers c 
        WHERE c.team_id = ak.user_id  -- 直接使用 user_id 作为 team_id
        AND c.name = 'Default Consumer'
        LIMIT 1
    )
WHERE consumer_id IS NULL;
```

### 3.3 为 usage_logs 回填维度字段

```sql
-- 通过 api_keys 反查
UPDATE usage_logs ul
SET 
    team_id = COALESCE(ak.team_id, ul.user_id),
    consumer_id = ak.consumer_id,
    department_id = ak.department_id
FROM api_keys ak
WHERE ul.api_key_id = ak.id
  AND ul.team_id IS NULL
  AND ul.created_at > NOW() - INTERVAL '30 days';
```

### 3.4 为 team_members 匹配 consumer_id（用于 ScopeSelf）

> **注意：** 此迁移通过 `users.username` 与 `consumers.name` 按名称匹配，属于尽力而为。  
> 大小写、空格、编码差异可能导致匹配失败，`username` 为空时也会失败，consumer_id 将保持 NULL。  
> 建议 Phase 1 完成后让管理员通过前端手动关联，或直接跳过此迁移。

```sql
UPDATE team_members tm
SET consumer_id = (
    SELECT c.id FROM consumers c 
    WHERE c.team_id = tm.team_id 
      AND c.name = (SELECT username FROM users u WHERE u.id = tm.user_id)
    LIMIT 1
)
WHERE consumer_id IS NULL;
```

### 4.1 Key 设计

```go
package rediskey

import (
    "fmt"
    "net/url"
    "time"
)

// 团队级别
func TeamRequests(teamID int64, date time.Time) string {
    return fmt.Sprintf("stats:team:%d:%s:requests", teamID, date.Format("2006-01-02"))
}

func TeamCost(teamID int64, date time.Time) string {
    return fmt.Sprintf("stats:team:%d:%s:cost", teamID, date.Format("2006-01-02"))
}

func TeamTokens(teamID int64, date time.Time) string {
    return fmt.Sprintf("stats:team:%d:%s:tokens", teamID, date.Format("2006-01-02"))
}

// 部门级别
func DeptRequests(deptID int64, date time.Time) string {
    return fmt.Sprintf("stats:dept:%d:%s:requests", deptID, date.Format("2006-01-02"))
}

func DeptCost(deptID int64, date time.Time) string {
    return fmt.Sprintf("stats:dept:%d:%s:cost", deptID, date.Format("2006-01-02"))
}

// 消费者级别
func ConsumerRequests(consumerID int64, date time.Time) string {
    return fmt.Sprintf("stats:consumer:%d:%s:requests", consumerID, date.Format("2006-01-02"))
}

func ConsumerCost(consumerID int64, date time.Time) string {
    return fmt.Sprintf("stats:consumer:%d:%s:cost", consumerID, date.Format("2006-01-02"))
}

// 模型级别（对 modelName 进行 URL 编码，防止特殊字符破坏 Key 结构）
func ModelRequests(modelName string, deptID int64, date time.Time) string {
    safeModel := url.QueryEscape(modelName)
    return fmt.Sprintf("stats:model:%s:%d:%s:requests", safeModel, deptID, date.Format("2006-01-02"))
}

func ModelCost(modelName string, deptID int64, date time.Time) string {
    safeModel := url.QueryEscape(modelName)
    return fmt.Sprintf("stats:model:%s:%d:%s:cost", safeModel, deptID, date.Format("2006-01-02"))
}

// 扫描模式（用于定时任务，用 Scan 替代 Keys）
func ScanPattern(date time.Time) string {
    return fmt.Sprintf("stats:*:%s:*", date.Format("2006-01-02"))
}
```

### 4.2 数据写入

```go
package service

import (
    "context"
    "time"
    "github.com/redis/go-redis/v9"
)

type UsageRecorder struct {
    redis *redis.Client
}

func (r *UsageRecorder) Record(ctx context.Context, req *RecordRequest) error {
    today := time.Now()
    pipe := r.redis.Pipeline()
    
    // 团队维度
    teamKey := rediskey.TeamCost(req.TeamID, today)
    pipe.IncrByFloat(ctx, teamKey, req.Cost)
    pipe.Expire(ctx, teamKey, 7*24*time.Hour)
    
    // 部门维度
    if req.DepartmentID > 0 {
        deptKey := rediskey.DeptCost(req.DepartmentID, today)
        pipe.IncrByFloat(ctx, deptKey, req.Cost)
        pipe.Expire(ctx, deptKey, 7*24*time.Hour)
    }
    
    // 消费者维度
    if req.ConsumerID > 0 {
        consumerKey := rediskey.ConsumerCost(req.ConsumerID, today)
        pipe.IncrByFloat(ctx, consumerKey, req.Cost)
        pipe.Expire(ctx, consumerKey, 7*24*time.Hour)
    }
    
    // 模型维度
    if req.ModelName != "" && req.DepartmentID > 0 {
        modelKey := rediskey.ModelCost(req.ModelName, req.DepartmentID, today)
        pipe.IncrByFloat(ctx, modelKey, req.Cost)
        pipe.Expire(ctx, modelKey, 7*24*time.Hour)
    }
    
    _, err := pipe.Exec(ctx)
    return err
}
```

### 4.4 定时同步任务（Redis → PostgreSQL）

```go
package task

import (
    "context"
    "time"
    "github.com/redis/go-redis/v9"
)

type RedisSyncTask struct {
    redis *redis.Client
    repo  StatsRepository
}

func (t *RedisSyncTask) Run(ctx context.Context) error {
    yesterday := time.Now().AddDate(0, 0, -1)
    pattern := rediskey.ScanPattern(yesterday)
    
    // 使用 Scan 替代 Keys，避免阻塞 Redis
    var cursor uint64
    var allKeys []string
    
    for {
        var batch []string
        var err error
        batch, cursor, err = t.redis.Scan(ctx, cursor, pattern, 100).Result()
        if err != nil {
            return err
        }
        allKeys = append(allKeys, batch...)
        if cursor == 0 {
            break
        }
    }
    
    if len(allKeys) == 0 {
        return nil
    }
    
    // 批量读取值
    values, err := t.redis.MGet(ctx, allKeys...).Result()
    if err != nil {
        return err
    }
    
    // 解析并分组
    stats := t.parseStats(allKeys, values, yesterday)
    
    // 写入 PostgreSQL（事务）
    tx, err := t.repo.BeginTx(ctx)
    if err != nil {
        return err
    }
    defer tx.Rollback()
    
    if err := t.repo.UpsertTeamDailyBatch(ctx, tx, stats.TeamStats); err != nil {
        return err
    }
    if err := t.repo.UpsertDeptDailyBatch(ctx, tx, stats.DeptStats); err != nil {
        return err
    }
    if err := t.repo.UpsertConsumerDailyBatch(ctx, tx, stats.ConsumerStats); err != nil {
        return err
    }
    if err := t.repo.UpsertModelDailyBatch(ctx, tx, stats.ModelStats); err != nil {
        return err
    }
    
    if err := tx.Commit(); err != nil {
        return err
    }
    
    // 确认写入成功后，删除 Redis Key（只删除昨日及以前）
    for _, key := range allKeys {
        t.redis.Del(ctx, key)
    }
    
    return t.repo.UpdateWatermark(ctx, time.Now())
}
```

```go
import (
    "context"
    "net/http"

type DataScope string

const (
    ScopeTeam       DataScope = "team"
    ScopeDepartment DataScope = "department"
    ScopeSelf       DataScope = "self"
)

type TeamMemberInfo struct {
    TeamID       int64
    UserID       int64
    Role         string
    DepartmentID *int64
    ConsumerID   *int64
    DataScope    DataScope

func TeamPermission(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        teamID := chi.URLParam(r, "team_id")
        userID := r.Context().Value("user_id").(int64)
        
        member, err := teamMemberRepo.Get(r.Context(), teamID, userID)
        if err != nil {
            http.Error(w, "Forbidden", http.StatusForbidden)
            return
        }
        
        var scope DataScope
        switch member.Role {
        case "owner", "admin":
            scope = ScopeTeam
        case "member", "viewer":
            scope = ScopeDepartment
        default:
            scope = ScopeSelf
        }
        
        ctx := context.WithValue(r.Context(), "team_member", &TeamMemberInfo{
            TeamID:       member.TeamID,
            UserID:       member.UserID,
            Role:         member.Role,
            DepartmentID: member.DepartmentID,
            ConsumerID:   member.ConsumerID,
            DataScope:    scope,
        })
        
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}
```

```go
func (s *AnalyticsService) GetDepartmentRanking(ctx context.Context, teamID int64, req *RankingRequest) (*RankingResponse, error) {
    member := ctx.Value("team_member").(*TeamMemberInfo)
    
    query := s.repo.NewQuery().Where("team_id = ?", teamID)
    
    switch member.DataScope {
    case ScopeTeam:
        // 无额外过滤
    case ScopeDepartment:
        if member.DepartmentID != nil {
            query = query.Where("department_id = ?", *member.DepartmentID)
        }
    case ScopeSelf:
        if member.ConsumerID != nil {
            query = query.Where("consumer_id = ?", *member.ConsumerID)
        }
    }
    
    return query.OrderBy("cost DESC").Limit(req.Limit).Find(ctx)
}
```

### 5.4 消费者离职自动回收

```go
func (s *ConsumerService) Deactivate(ctx context.Context, consumerID int64) error {
    // 1. 更新状态
    if err := s.repo.UpdateStatus(ctx, consumerID, "disabled"); err != nil {
        return err
    }
    
    // 2. 设置离职时间
    now := time.Now()
    if err := s.repo.SetDeactivatedAt(ctx, consumerID, now); err != nil {
        return err
    }
    
    // 3. 自动禁用所有 API Key
    keys, err := s.apiKeyRepo.ListByConsumer(ctx, consumerID)
    if err != nil {
        return err
    }
    
    for _, key := range keys {
        if err := s.apiKeyService.Disable(ctx, key.ID); err != nil {
            s.logger.Warn("failed to disable api key", "key_id", key.ID, "error", err)
        }
    }
    
    // 4. 审计日志
    s.auditLogRepo.Insert(ctx, &AuditLog{
        TeamID:        s.getTeamID(ctx, consumerID),
        UserID:        ctx.Value("user_id").(int64),
        Action:        "deactivate",
        OperationType: "auto_revoke",
        ResourceType:  "consumer",
        ResourceID:    consumerID,
        Changes:       map[string]interface{}{"disabled_keys_count": len(keys)},
    })
    
    return nil
}
```

### 13.2 Usage Log 热路径影响（关键决策）

现有 `usage_logs` 写入经过以下热路径：

```
Gateway Handler → submitUsageRecordTask → UsageRecordWorkerPool
  → recordUsageCore → buildRecordUsageLog → UsageLogRepository.Create
    → prepareUsageLogInsert → SQL INSERT
```

**如果按 2.7 节给 `usage_logs` 加 `team_id`/`department_id`/`consumer_id`，需要修改 7 处代码：**

| 位置 | 文件 | 修改内容 |
|------|------|---------|
| `UsageLog` 结构体 | `service/usage_log.go:98` | 加 3 个字段 |
| `buildRecordUsageLog` | `service/gateway_service.go:9765` | 从 API Key 填充 |
| `prepareUsageLogInsert` | `repository/usage_log_repo.go:1427` | 加参数映射 |
| `usageLogInsertArgTypes` | `repository/usage_log_repo.go:41` | 加 3 个类型声明 |
| `createSingle` INSERT SQL | `repository/usage_log_repo.go:406` | 加列名 |
| `buildUsageLogBatchInsertQuery` | `repository/usage_log_repo.go:931` | 加列名 |
| `buildUsageLogBestEffortInsertQuery` | `repository/usage_log_repo.go:1132` | 加列名 |

**建议方案：** `usage_logs` 不加冗余字段，改为在聚合查询时通过 `api_keys` JOIN 反查。这样热路径零改动，风险最低。代价是聚合查询多一次 JOIN，但聚合是后台定时任务，不敏感。

**如果选择加字段，需注意：**
- `buildRecordUsageLog` 中需要通过 `apiKey` 对象获取 `team_id`，需要先扩展 `APIKey` 结构体
- API Key 认证中间件（`api_key_auth.go`）中需要加载 `team_id`/`consumer_id`/`department_id` 并缓存
- 所有 INSERT SQL 模板（3 处）都需要同步修改

### 13.4 AuthSubject 扩展

现有 `AuthSubject` 结构体只包含 `UserID` 和 `Concurrency`：

```go
type AuthSubject struct {
    UserID      int64
    Concurrency int
}
```

团队管理 API 需要额外的角色信息。建议方案：**不修改 AuthSubject，新增独立中间件**。

在 `server/middleware/team_permission.go` 中实现 `TeamPermissionMiddleware`，通过 `JWT Auth` 认证后的 `AuthSubject.UserID` 查询 `team_members` 表，将 `TeamMemberInfo` 注入到 `gin.Context`。团队管理路由组使用此中间件，非团队路由不受影响。

### 13.5 现有 Dashboard 查询兼容性

现有 `UsageHandler` 的以下接口按 `user_id` 查询：

| 接口 | 问题 |
|------|------|
| `GET /api/v1/usage/dashboard/stats` | 只查当前用户的用量 |
| `GET /api/v1/usage/dashboard/trend` | 同上 |
| `GET /api/v1/usage/dashboard/models` | 同上 |

在团队模式下，如果 member 用自己的 API Key 消费，`usage_logs.user_id = member.id`，owner 的 dashboard 看不到 member 的用量。

**解决方案：** 新增按 `team_id` 查询的接口（已在 6.5 节定义），不修改现有接口。owner/admin 切换到团队视图时调用新接口，member/viewer 继续使用原接口。

### 13.6 聚合表 Pipeline 复用建议

现有系统已有 `DashboardAggregationService` 定时聚合 `usage_dashboard_hourly` → `usage_dashboard_daily`。方案新增 4 张 `team_usage_*` 聚合表和独立同步任务，造成两套 Pipeline 并行。

**建议方案一（推荐）：扩展现有聚合表**
在 `usage_dashboard_daily` 上加 `team_id`/`department_id`/`consumer_id` 维度字段（nullable），复用现有 `DashboardAggregationService` 和 Leader Lock。聚合 SQL 中通过 `usage_logs JOIN api_keys` 反查维度。

**建议方案二（保持现状）：独立聚合 Pipeline**
如保持独立，需注意：
- 聚合任务使用独立的定时器（`TimingWheelService.ScheduleRecurring`）
- 使用独立的 Leader Lock Key（避免与现有聚合冲突）
- `usage_logs` 清理策略需要等待两种聚合都完成
- 聚合 SQL 中通过 `usage_logs JOIN api_keys` 反查维度（无需改 usage_logs 表结构）

### 13.7 API Key 模型扩展

现有 `APIKey` 结构体（`service/api_key.go`）需要新增字段：

```go
type APIKey struct {
    // ... 现有字段
    TeamID       *int64 `json:"team_id,omitempty"`
    ConsumerID   *int64 `json:"consumer_id,omitempty"`
    DepartmentID *int64 `json:"department_id,omitempty"`
}
```

API Key 认证中间件（`api_key_auth.go:86`）在加载 API Key 时需要同时加载这些字段，并缓存到 Redis，避免每次请求都 JOIN。
